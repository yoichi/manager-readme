# この文書について

エンジニアリングマネージャーとして私が関わるメンバーに向けて、私が普段どういうものの見方をしているのか知ってほしいと思い、書いたものです。

# マネージャーの役割

長期的な視点で組織が出す価値を最大化するために、メンバーの活動を支援することが、マネージャーとしての私の最も大切な役割です。あなたのためのツールだと思ってうまく活用してください。

メンバーとの対話に時間を使います。話したい内容が整理できてない状態でも構いません。話しましょう。私のカレンダーの空いているところに予定を入れていただいても構いませんし、言ってもらえば私の方で予定調整します。また、定期的に1on1の時間を持ちます。

現場の観察に時間を使います。起こっていることを知り、私がなすべきことを考えます。ふらっとミーティングを見学させてもらうことがありますが、あるがままを見せてくれるとありがたいです。

# 情報共有

情報は可能な限りオープンにしたいと思っています。意思決定には情報が必要であり、意思決定に関わる人を増やしたいからです。

見ようと思えば見れる状態で情報を配置するだけでは、情報共有として不十分だと思っています。伝えるべき相手に対しては、情報の配置を認識してもらい、内容を把握してもらえるよう支援します。

私自身が適切な意思決定をできるよう、情報を収集します。情報提供にご協力よろしくお願いします。ありもののドキュメントや、関連するやりとりの記録をそのまま渡して(URLを教えて)いただけるとありがたいです。改めて整理しなおす手間をかけていただくよりも、あなたが伝えるべき相手に伝えた時の情報があれば、それをそのまま共有いただけるとありがたいです。

# コメント

現場を観察して思ったことを伝えることがありますが、こうしてくださいと明確にお願いしない限りは、あくまで私の意見であり、指示ではないと捉えてください。意見を受け止めた上で、それに対して何らかの行動をとるかどうかはチームに委ねます。もし見当違いな意見と感じたら率直に教えていただけると助かります。意見なのか指示なのか不明確な場合は尋ねてください。

また、何かをお願いしたとき、必ずしも言われた人が自身で対応しなければならないとは考えないでください。担当のアサインは基本的にチームに委ねたいと思っています。

# コミュニケーション

完璧なコミュニケーションは存在しないと考えています。どんなに注意していても、どんなに言葉を紡いでも、コミュニケーションミスは発生します。一方、解けない誤解はないとも思っています。誤解やすれ違いが生じたら、話しましょう。

単純な内容の伝達ミスの他に、あなたが私にどういう立場で話を聞いて欲しいかの期待を私が知らないことで、ちぐはぐのフィードバックをしてしまうことがあり得ます。例えばただ話を聞いて知って欲しいだけなのに余計な助言をしてしまったり、逆に意見が欲しいのに黙ってただ聞くだけになってしまうなど。生成AIとの対話時に配役を伝えるのと同じように、対話の際に期待を伝えていただくと、そういうコミュニケーションミスの発生確率は下げられると思います。

# ルール

規定やガイドラインは、運用上の迷いを抑え、著しい不公平が生じないようにして皆さんが活動しやすくなるよう、皆さんのために存在しています。もしそれらが皆さんの活動の妨げになっていると感じた場合は相談してください。ルールの解釈で誤解が生じていたり、環境の変化によりルールの見直しが必要になっているかもしれません。

また、全体に向けたルールでは個別のコンテクストを考慮しきれていないことがあります。ご自身にとってルールの制約がゆるすぎるあるいはきつすぎると感じた場合、個別の例外対応ができる場合もあるので、相談してください。

# おわりに

私の行動、言動について感じたことあれば率直なフィードバックをいただけるとうれしいです。

特に「あなたのためにならないことをしている」と感じた時は教えて欲しいです。私は完璧な人間ではないので間違うことがありますが、最初に書いた通り、皆さんを支援することが私の最も大切な役割であり、間違いに気付いて直し、役割を果たすチャンスをいただけるとありがたいです。

ここに書いたことは、書いた時点での私の考えであり、日々の活動を通して考えが変わった場合は更新します。
